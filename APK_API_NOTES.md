# Результаты проверки API в APK

В AllPredictor 4.4.23 обнаружены следующие технические ориентиры:

- `https://allpredictor.com/api/ai/groq` — серверный AI-анализ;
- `football-data.org`;
- `/api/football/v4/matches`;
- `/api/football/v4/competitions/`;
- `v1.basketball.api-sports.io`;
- `v1.hockey.api-sports.io`;
- `v1.volleyball.api-sports.io`;
- `v1.handball.api-sports.io`;
- `v1.baseball.api-sports.io`;
- `v1.rugby.api-sports.io`;
- `v1.american-football.api-sports.io`;
- `v1.afl.api-sports.io`;
- `v1.formula-1.api-sports.io`;
- заголовок авторизации `X-API-Key`;
- хранилище прогнозов `locked_predictions_v2`.

Спортивная логика находится в AOT-компиляции Flutter `libapp.so`. Готовых
исходников Dart и отдельной HTML-реализации в APK нет.

## Ключи

Повторное сканирование не обнаружило переносимого спортивного API-ключа в
открытом виде. В ресурсах присутствует клиентская конфигурация Firebase,
привязанная к проекту разработчика APK. Она намеренно не скопирована:

- это не ключ к спортивным API;
- она не даёт права использовать чужой Firebase-проект;
- её публикация может создать риск злоупотребления и блокировки.

Вероятнее всего, часть данных и закрытых ключей остаётся на сервере
`allpredictor.com`, загружается удалённо или защищена правилами Firebase.

## Правильное подключение

Для живых данных следует выпустить собственные ключи у Football‑Data и
API‑Sports, хранить их только на сервере и выдавать браузеру уже очищенный JSON.
Статический GitHub Pages не предназначен для безопасного хранения секретов.

Теннис в APK присутствует только как название категории. Отдельный
`TennisPage`, `TennisService` или теннисный API при анализе не обнаружены,
поэтому теннисный модуль страницы создан отдельно.
